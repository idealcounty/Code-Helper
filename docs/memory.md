# Code Helper 记忆系统设计与开发目标

## 1. 目标

Code Helper 的记忆系统需要区分“上下文”“会话恢复”和“跨对话长期记忆”，避免把能够查看历史对话误认为 Agent 已经记住了历史事实。

目标是让 Agent 在不依赖 Agent 框架和外部向量数据库的前提下，能够：

1. 在当前对话中保留最近消息、工具结果和计划。
2. 在上下文超出预算时压缩较早历史，而不丢失完整事件日志。
3. 程序重启后恢复指定会话的消息、计划和统计信息。
4. 把经过用户确认的重要项目事实持久化，并在新对话中按任务相关性自动召回。
5. 允许用户或 Agent 查询、修正和遗忘长期记忆。
6. 让长期记忆可追踪、可删除、限制长度，并且不能绕过工具权限。

## 2. 已有能力

### 2.1 当前对话上下文

- `AgentState.messages` 保存当前会话的用户消息、模型回复和工具结果。
- 默认保留最近 48 条消息。
- 单条消息最多保留约 20,000 字符。
- 总上下文使用约 80,000 字符预算。
- 较早历史会生成确定性的摘录摘要，并发布 `context_compacted` 事件。
- 工具长输出保留头尾，完整内容写入 `.code-helper/tool-results/`。

### 2.2 会话持久化与恢复

- 每个会话以 JSONL 事件保存到 `.code-helper/sessions/`。
- Web UI 可以列出同一工作区的历史会话。
- 选择历史会话时，可恢复消息、计划、Token、工具统计和最终状态。
- 当前恢复粒度是“对话级恢复”，不能从进程中断的某一个工具步骤继续执行。

### 2.3 当前剩余限制

- 项目与用户长期记忆已经可跨对话召回，但候选提取仍是确定性规则，不等同于完整语义理解。
- 当前 Step 级历史压缩已复用 reducer 生成的结构化事实摘要，包含目标、计划、工具证据、验证和下一步；它与 Turn Summary 分工不同，后者仍负责 Turn 结束后的长期记忆候选。
- 文件摘要缓存仅存在于当前进程内；程序重启后会重新生成。
- 可选 Embedding 接口已经具备，但默认运行路径仍采用本地词法检索，尚未绑定特定向量服务。
- Session 仍只能恢复对话和可观察状态，不能从中断的写操作或命令中自动继续执行。

## 3. 记忆分层

| 层级 | 生命周期 | 内容 | 当前目标 |
| --- | --- | --- | --- |
| 工作记忆 | 单个 Step / Turn | 当前模型输入、工具 Observation | 已实现 |
| 会话记忆 | 一个 Session | 多轮消息、计划、轨迹、统计 | 已实现基础版 |
| 项目记忆 | 同一工作区的多个 Session | 事实、决策、偏好、待办 | 已实现 V3 |
| 用户记忆 | 多个工作区 | 通用偏好、个人习惯 | 已实现可选版 |

## 4. 项目级长期记忆 V1

### 4.1 存储位置

```text
.code-helper/memory/memories.jsonl
```

采用只追加 JSONL 记录。更新和删除不会改写历史行，而是追加新的 `upsert` 或 `delete` 事件，便于审计和恢复。

### 4.2 记忆类型

- `fact`：稳定的项目事实，例如技术栈、入口文件和约束。
- `decision`：已经确认的架构或实现决策及其结果。
- `preference`：用户在本项目中的工作偏好。
- `task`：需要在后续会话继续处理的事项。

### 4.3 记忆字段

```json
{
  "operation": "upsert",
  "id": "memory-id",
  "category": "decision",
  "content": "前端使用原生 HTML/CSS/JavaScript，不引入 React 构建链。",
  "keywords": ["frontend", "javascript", "architecture"],
  "importance": 4,
  "subject": "frontend-stack",
  "file_paths": ["src/coding_agent/web/static/app.js"],
  "symbols": ["renderIntelligence"],
  "scope": "project",
  "source_session_id": "...",
  "source_turn_id": "...",
  "created_at": "...",
  "updated_at": "..."
}
```

### 4.4 写入策略

- `remember_project_memory` 是写操作，只在 Act 模式可用并经过用户批准。
- 不把所有聊天内容自动写成长期记忆，避免错误信息和模型猜测污染记忆库。
- 适合写入的内容包括用户明确要求记住的事实、已确认决策、稳定偏好和跨会话待办。
- 单条内容限制为 2,000 字符，关键词数量和长度也受限制。

### 4.5 召回策略

- `search_project_memory` 可以在所有模式下读取项目记忆。
- 构造模型上下文时，使用最新用户任务自动检索最多 6 条相关记忆。
- V1 使用确定性的词项、中文片段、重要度和新近度评分，不依赖 Embedding 服务。
- 召回内容限制在 4,000 字符内，并明确标记为“可能过期的项目记录”，不能覆盖安全策略和当前文件事实。

### 4.6 遗忘策略

- `forget_project_memory` 追加删除事件，不物理擦除审计历史。
- 遗忘属于破坏性操作，只在 Act 模式可用并要求批准。
- 被删除的记忆不再参与搜索和上下文注入。

## 5. 验收标准

项目级记忆 V1 完成时应满足：

- [x] 记忆能够跨 `MemoryStore` 实例和程序重启持久化。
- [x] 可以按任务关键词、类型和重要度检索。
- [x] 新会话能够自动注入相关项目记忆。
- [x] Agent 可以使用工具显式写入、搜索和遗忘记忆。
- [x] 写入和遗忘沿用现有权限管线。
- [x] 前端“智能”面板能看到记忆数量和最近记忆。
- [x] 记忆文件位于工作区 `.code-helper/`，不会进入业务代码上下文或 Git 提交。
- [x] 自动化测试覆盖持久化、召回、删除、上下文注入和 Web 状态。

## 6. 后续阶段

### V2：高保真会话总结

- [x] 每轮结束时生成结构化总结：目标、完成项、修改文件、验证证据、决策和未完成事项；保存于 `.code-helper/memory/summaries/`。
- [x] 总结生成失败时发布 `session_summary_failed`，保留 `turn_finished` 和原始事件，不改变本轮完成结果或覆盖已有记忆。
- [x] 候选事实默认保持 `pending`；用户可在“智能”面板或记忆工具中确认、忽略，只有确认后才提升为项目长期记忆。

### V3：更智能的召回

- [x] 增加文件路径、符号和会话来源过滤。
- [x] 支持词法检索与可选 Embedding 混合排序；未配置或服务失败时自动退化为确定性词法检索。
- [x] 同一 `category + subject` 的不同结论作为冲突同时返回，标注新旧关系及关联文件在当前仓库中是 `verified / partial / missing`，不会静默丢弃旧结论。

### V4：用户级记忆

- [x] 默认关闭；用户通过环境配置、工具或“智能”面板明确启用后，才会在工作区之外保存和召回通用偏好。
- [x] 项目与用户记忆使用不同目录和带作用域约束的 `MemoryStore`，运行时拒绝把用户记忆目录配置到当前工作区内。
- [x] 提供工具与 Web UI 的导出、清空、启用和禁用入口。

## 7. 当前验收结果

- 结构化总结和候选确认不会阻塞或污染原始会话事件。
- 新会话会自动召回相关项目记忆；用户记忆仅在启用时参与，并以独立上下文段落注入。
- “智能”面板展示项目记忆、待确认候选、会话总结数量和用户记忆状态，可直接确认、忽略、导出、清空或停用。
- 自动化测试覆盖 V1 至 V4 的持久化、失败降级、筛选、混排、冲突、分域及用户控制。

## 8. 持续可靠性优化

- 同一进程内指向同一 JSONL 的多个 `MemoryStore` 共享可重入锁，去重、更新和删除按完整的“读取当前状态—追加事件”事务串行执行。
- 加载审计日志时会校验类型、长度、时间戳和 `scope`；损坏、未知操作或跨作用域记录不会进入召回，并通过 `invalid_records` 统计暴露，但不会改写原始审计文件。
- 面向界面的列表和召回仍限制返回数量；用户记忆导出、清空和总数统计处理全部有效记录，不会在 500 条时静默截断。
- 混合排序增加可解释的 `recency_score`。当某条命中记忆存在相同 `category + subject` 的冲突结论时，会在结果限额内成组返回冲突内容，而不只返回冲突 ID。
- 项目记忆和用户记忆都以最后一条真实用户消息作为自动召回查询，忽略 Agent Loop 写入的 `SYSTEM OBSERVATION`。
- 同一总结目录中的候选确认与忽略操作串行执行；并发请求中只有第一个请求能够改变 `pending` 状态。
